# EOT 对比验证：Mac 与 Pi5

日期：2026-10-17。范围：模型预选、输入契约、跨平台推理、现有话轮架构和 SDK 生命周期。生产模型与配置未切换。

## 结论

没有一个候选可以仅凭本轮结果直接替换生产 EOT，并同时证明“接话更快、抢话更少、完整理解等待和附和”。推荐把 LiveKit mini 与 TurnSense 1.0 留作后续集成影子评测候选；前者在真实停顿区分和框架集成上有优势，后者在中文片段语义与开放 ONNX 交付上有优势。生产中最终只选一个主检测器，不叠加投票。

不建议现在采用 TurnSense 1.1：中文片段有小幅提升，但模型体积与推理开销明显增大，真实话轮没有显示明确的对应收益。不建议直接改 FireRed 为官方预处理：相同官方权重下，本次两组数据的效果均下降。

**最需要优化的是证据与动作的边界：结束证据不能独自授权回答；停止旧播放也不能等同于提交新请求。** 具体方案见 [EOT 优化方案](eot-optimization-proposal-2026-10-17.md)。

## 测试覆盖与复现

- 四个模型家族、六个配置；每个配置在两台机器各跑 1,494 个输入，共 17,928 条正式预测；另各做 120 次热身后重复计时，共 1,440 次。
- Easy-Turn：完整 150、不完整 150、附和 50、等待 50，全部选公开 real 子集。片段准确率只在前两类的 300 条上计算；附和和等待单独分析。
- LiveKit 中文集：完整收录 344 个话轮；保留 608 个句中停顿、344 个最终停顿，共 952 个决策点。短于 200 ms 的停顿不参与；句中停顿超过 5 s 按上游规则排除。
- 其余输入：80 个尾部静音变化、40 个确定性加噪声/降音量样本、22 个项目已有 TTS 素材。它们是诊断用例，不算额外独立真人样本。
- 175 个话轮用于调参，169 个话轮保留测试，后者包含 301 个句中停顿。按话轮 ID 固定划分，所有属于同一话轮的停顿始终同组。公开数据不提供说话人/会话 ID，不能声称完成了按说话人隔离的泛化验证。
- 806 份标准化音频已逐文件核对 Mac/Pi5 SHA-256；952 个决策点逐一检查音频及文字没有使用未来信息。候选权重及前端工件也已核对两端摘要。
- 复用官方 eot-bench 的策略扫描、Smart Turn 特征/预测实现、TurnSense 前端/输出解码，以及安装版 LiveKit 原生运行时。没有另写一套模型或 endpointing 引擎。

硬件：Mac 为 Apple M3 Pro / 36 GiB；Pi5 为 8 GiB ARM64，原有 Channel/Agent 服务保持运行。两端 livekit-agents 1.7.1、livekit-local-inference 0.2.7、ONNX Runtime 1.26.0、NumPy 2.4.4、Transformers 5.8.0、PyTorch 2.10.0。ONNX 使用 CPU、2 个 intra-op 线程、1 个 inter-op 线程；Pi 测试 nice=10。各机器按模型顺序执行，避免候选互相争抢 CPU。测试没有播放扬声器。

这些是不同输入路线的部署比较：LiveKit 使用最近 1.2 s 音频，Smart Turn / TurnSense 使用最多 8 s，FireRed 使用文字。音频模型不承担 ASR 到达等待，文本模型也没有获得完美实时 ASR；因此还补做了零转写延迟消融，见下文。公开基准可能已被候选用于开发或调参，无法核实所有训练重叠；本轮保留集隔离只保证我们的调参没有读取它，不能证明模型从未见过。

## 模型结果

准确率为公开真人片段的二分类结果；AUC 为真实话轮停顿区分能力，越高越好。二者衡量不同能力，不能互相替代。p95 包含特征提取和模型推理，不包含音频文件读取、ASR、网络、LLM、TTS 或设备播放。RSS 为整个评测进程，含 Python/依赖/模型，不能当作纯权重大小。

| 配置 | 片段准确率 Mac / Pi5 | 真实停顿 AUC Mac / Pi5 | 推理 p95 Mac / Pi5 | Pi5 RSS |
|---|---:|---:|---:|---:|
| LiveKit v1-mini | 61.3% / 61.3% | 0.824 / 0.824 | 7.6 / 117.9 ms | 531 MB |
| Smart Turn v3.2 INT8 | 76.0% / 76.7% | 0.749 / 0.748 | 19.6 / 114.3 ms | 363 MB |
| TurnSense 1.0 INT8 | 95.0% / 95.3% | 0.681 / 0.680 | 41.4 / 141.1 ms | 422 MB |
| TurnSense 1.1 INT8 | 97.0% / 97.3% | 0.676 / 0.676 | 132.4 / 468.0 ms | 853 MB |
| FireRed 当前预处理 | 92.7% / 92.3% | 0.552 / 0.551 | 32.7 / 114.5 ms | 832 MB |
| FireRed 官方预处理 | 78.3% / 78.3% | 0.518 / 0.519 | 37.6 / 154.0 ms | 846 MB |

片段使用 p_complete ≥ 0.5；LiveKit 使用 SDK 随包中文阈值 0.355。TurnSense 在这 300 条上使用原生 argmax 与该阈值得到相同分类。FireRed 在片段集使用参考转写，在话轮集使用截至判定时刻减去 500 ms 可见的参考词；因此它是文本模型基线，不是生产 ASR 的端到端准确率。

### 对真实接话的影响

复用 eot-bench，在调参集扫描阈值、最小静音与最大等待；模型在停顿 200 ms 处读取因果前缀，分数在实测前端+推理耗时后才可用。冻结每台机器选出的参数后评估保留集。以下为“调参集误截断预算 5%”的结果，**并不表示保留集也达到了 5%**。这是单次评分的策略回放，不是实际设备可听延迟。

| 配置（Pi5） | 保留集停顿误截断 | 发生抢话的话轮 | 平均 EOT 等待 | p95 等待 | 超时结束占比 |
|---|---:|---:|---:|---:|---:|
| LiveKit v1-mini | 29/301（9.6%） | 24/169（14.2%） | 797 ms | 1500 ms | 21.9% |
| Smart Turn v3.2 INT8 | 26/301（8.6%） | 21/169（12.4%） | 833 ms | 800 ms | 4.7% |
| TurnSense 1.0 INT8 | 18/301（6.0%） | 14/169（8.3%） | 991 ms | 1500 ms | 27.2% |
| TurnSense 1.1 INT8 | 17/301（5.6%） | 13/169（7.7%） | 1020 ms | 1500 ms | 31.4% |
| FireRed 当前预处理 | 16/301（5.3%） | 15/169（8.9%） | 1000 ms | 1000 ms | 100.0% |
| FireRed 官方预处理 | 16/301（5.3%） | 15/169（8.9%） | 1000 ms | 1000 ms | 100.0% |

误截断分母是句中停顿；话轮抢话分母是全部 169 个保留话轮。结果中已包含按话轮聚类 bootstrap 的 95% 区间，见原始 comparison.json。样本有限且区间重叠，不能把几个百分点差异当成确定胜负。

FireRed 的该工作点主要依赖 1 s 超时，不能将表中的低抢话率归功于语义模型。其当前 0.5 阈值加 300 ms/3 s 固定时序的对照，以及 2%/10% 调参预算结果也保留在 JSON 中。固定时序只用于横向比较，不代表当前完整产品链路。

### 附和与等待

| 配置（Pi5） | 附和得到高完成分数 | 等待得到高完成分数 |
|---|---:|---:|
| LiveKit v1-mini | 22% | 24% |
| Smart Turn v3.2 INT8 | 74% | 94% |
| TurnSense 1.0 INT8 | 70% | 42% |
| TurnSense 1.1 INT8 | 62% | 80% |
| FireRed 当前预处理 | 34% | 50% |
| FireRed 官方预处理 | 60% | 64% |

这些高分不一定是 EOT 模型的错误：“等一下”本身可以是一句已经说完的话。问题在于如果系统把 EOT 高分直接映射为“可以回答”，就会违反用户希望等待或继续播放的意图。因此产品策略必须保留独立的交互意图。

### 文字到达时机对照

额外在两端各运行 2 × 952 次 FireRed 预测，只把参考词到达延迟从 500 ms 改为 0。661 个决策点的文字发生变化；零延迟仍受当前判定时刻的词边界约束，没有读入未来词。它是理想文字可用性对照，不是可实现的 ASR 延迟承诺。

| 配置 | Mac AUC：500 ms / 0 ms | Pi5 AUC：500 ms / 0 ms |
|---|---:|---:|
| FireRed 当前预处理 | 0.552 / 0.552 | 0.551 / 0.552 |
| FireRed 官方预处理 | 0.518 / 0.525 | 0.519 / 0.526 |

在本集上，提前获得参考文字没有明显改善 FireRed 的停顿区分能力，因此不能把主测试的低 AUC 全部归因于 500 ms 转写延迟；也不能外推为所有真实 ASR 情况。

## 跨平台与集成验证

| 配置 | 1,494 个输入中的阈值判定差异 | 最大分数差 |
|---|---:|---:|
| LiveKit v1-mini | 0 | 0.000007 |
| Smart Turn v3.2 INT8 | 14 | 0.406693 |
| TurnSense 1.0 INT8 | 8 | 0.082177 |
| TurnSense 1.1 INT8 | 17 | 0.137296 |
| FireRed 当前预处理 | 5 | 0.185177 |
| FireRed 官方预处理 | 7 | 0.399189 |

对 Smart Turn、TurnSense 1.0、当前 FireRed 各取三个最大差异样本，固定输入重复推理 5 次，再把 Mac 的实际模型输入送入 Pi5：

- **Smart Turn**：特征最大差异仅约 6.2e−6～1.65e−5，但原始分数差异可达 0.407。Pi5 使用 Mac 特征后，三个样本都精确恢复 Mac 输出；这把这些样本的分歧定位到了前端微小数值差异及模型对此的敏感性，不能简单归咎于 ONNX CPU 输出不同。
- **TurnSense 1.0**：换成 Mac 特征后仍残留输出差异，说明前端和推理运行路径都需要纳入平台验证；尚未定位到具体算子。
- **当前 FireRed**：token IDs 和 mask 完全一致，输出仍不同。结合相同权重摘要，说明差异发生在两端推理路径；尚未定位到具体内核。
- 九个样本各自在固定输入下重复 5 次的结果完全一致，排除了这些探针中的随机重复抖动。LiveKit mini 在全量 1,494 条上没有跨平台阈值翻转。

结论：固定权重、依赖版本和阈值不等于跨平台行为一致。进入影子评测前必须固定完整前端与推理工件，并在目标设备校准；本轮未通过舍入特征或修改阈值掩盖差异。原始探针见各 host/features/summary.json。

- 两端现有核心架构回归：各 122 passed、11 xfailed。追加续说、播放证据、误打断恢复和取消重置回归：各 32 passed。
- 11 个预期失败中，4 个是短句 EOT 分数、1 个是完整短句延迟、6 个属于未提供语义分类器的默认策略夹具。它们不能被解释为当前已配置 LLM 意图分类器的线上状态全部失败，也不能算成通过。
- 上游 eot-bench 指标、输入转换及候选适配器相关回归：21 passed。
- 两端原生流式 SDK 探针：6 份音频分帧输入与直接推理一致；覆盖旧请求被新请求取代、flush 作废、关闭流与当前包装器协议边界。
- 当前 InterruptAwareTurnDetector 只满足文本调用方式，不满足流式协议。直接替换模型对象会丢失流式能力，后续需要按 SDK 支持的流式生命周期接入。
- 已验证关闭流后 SDK predict 返回默认 1.0；它不是模型的置信结果。模型证据必须区分有效预测、过期、缺失与降级，不能让默认值冒充完成证据。

## 验证边界

Pi5 最终健康检查：Channel / Agent 均 active，温度 55.65°C，get_throttled=0x0。该结果说明此次隔离评测没有留下已观察到的服务故障或降频记录，不代表完成了线上并发容量测试。

本轮充分比较的是上述本地 CPU 候选。LiveKit 云端 v1、Easy Turn、VAP、FastTurn、HiThink Turn 没有冒充为已做两端模型实测：云端不是本地 CPU 路线；其余属于不同部署成本或研究路线。本轮没有据此宣布全球最优模型。

本轮没有把候选接入生产服务，也没有做新模型下的真人 BOX-3/Mobile 扬声器 HIL；没有测真实 ASR 错字、网络尾延迟或候选与线上 LLM/TTS 的最终听感。现有架构回归使用受控外部依赖，公开录音回放不能替代这些验收。用户体验的上线结论应在优化方案实现后通过这些验收，不能由离线分数保证。
