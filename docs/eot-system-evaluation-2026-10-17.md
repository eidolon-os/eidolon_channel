# EOT 系统评估与最终建议

日期：2026-10-17。状态：调研、隔离实验与方案评审完成；未修改生产模型、服务或配置。本文补充并收敛此前的[模型对比](eot-comparison-2026-10-17.md)和[优化方案](eot-optimization-proposal-2026-10-17.md)。

后续补充：用户提供 pplx/d3 快速决策服务后，两端完成 240 次真实请求。[决策模型对照](eot-decider-comparison-2026-10-17.md)修订本文关于语义分类的取舍：优先验证独立快速 decider，不再把“同次推理判断并回答”作为降低分类延迟的前置条件。本文原始实验结果保留。

## 1. 决策摘要

**选择“单一主 EOT 检测器 + 显式交互状态 + 证据并行 + 唯一提交屏障”的架构。主模型优先集成 LiveKit v1-mini，两台主机使用同一语义策略，按实际资源预算配置执行方式。TurnSense 1.0 保留为同接口替换候选，不与主模型长期级联。**

这是本轮证据支持的工程选择，不是“已证明新组合在真实 BOX3 上全面优于生产”的结论。生产发布建议仍是保留当前 FireRed 基线，待新组合通过真实 ASR、设备和副作用边界验收后再切换。本轮没有新做物理 BOX3 麦克风/扬声器、AEC 或实际用户盲测；Mac 真实 ASR 复核失败，不能宣布两端完整体验验证通过。

| 问题 | 选择 | 依据 / 限制 |
|---|---|---|
| 架构是否重建 | 保留 Channel / LiveKit，复用既有协调器 | 已有播放收尾、候选身份与提交职责；另建状态机增加双重所有权 |
| EOT 是否串联多个模型 | 默认一个主检测器 | 双模型级联在保留集收益小；双模型共同确认大量退化为超时 |
| 主模型先选谁 | LiveKit v1-mini 为首个产品集成候选 | 真实停顿 AUC、跨平台一致性、SDK 生命周期与 Mac 延迟较好；中文片段准确率较弱，必须保留语义判断 |
| 中文专项备选 | TurnSense 1.0 INT8 | 中文片段表现明显较好，但真实停顿收益不如片段指标亮眼 |
| 明确等待怎么处理 | 独立且持续的用户持有话轮状态 | 完整句子也可能要求不回答；一般 EOT 超时不得解除明确等待 |
| 是否再加串行完整性 LLM | 不作为所有普通话轮的默认新增步骤 | 真实分类调用 p50 约 1.25 s；会显著增加接话成本 |
| 如何避免额外 LLM 往返 | 目标采用同次推理先输出交互决策、再生成可暂存回答 | 30 个自编边界样例 29 个匹配；尚未验证 Agent RPC、工具与历史持久化，需要正式契约 |
| 是否按 host 差异化 | 执行配置必须差异化；语义规则统一 | 同模型线程和并发对 Mac/Pi5 的影响不同；没有证据支持按 OS 名称强制选不同模型 |

## 3. 架构与级联：实测比较

### 3.1 调度方式

当前 `InterruptAwareTurnDetector` 先等待打断/播放 settle，再执行 EOT。底层虽是 async 接口，FireRed 评分实际同步运行在事件循环；ASR 更新等其他路径也存在同步评分。正确改动范围是纯推理边界，而非只把一个外层函数包进线程。

固定 350 ms settle、2 个推理线程、每格 6 次调用的结果：

| 调度方式 | Mac 平均完成 / 最大循环延迟 | Pi5 平均完成 / 最大循环延迟 |
|---|---:|---:|
| 当前串行 | 371.7 / 39.8 ms | 382.3 / 76.1 ms |
| 串行等待 + 工作线程评分 | 371.5 / 2.3 ms | 380.4 / 0.9 ms |
| settle 与纯评分并行，提交前汇合 | 350.5 / 1.2 ms | 350.9 / 0.9 ms |

结论：移出事件循环首先改善响应性；并行可隐藏部分评分时间。不是所有延迟都能消失。取消等待任务时，原生推理仍继续运行，两端均复现；容量令牌必须等原生任务真正结束才释放。

真实 AgentSession、真实 FireRed、外部服务替身的配对验证结果：

| 输入 | Mac 当前 / 并行 | Pi5 当前 / 并行 |
|---|---:|---:|
| 给我讲一个笑话 | 255.6 / 254.9 ms | 254.3 / 253.4 ms |
| 换一个笑话 | 3,005.5 / 3,004.9 ms | 3,003.0 / 3,004.3 ms |
| 就这样吧 | 3,006.0 / 3,004.0 ms | 3,002.7 / 3,003.6 ms |
| 帮我详细介绍一下这个方案 | 254.4 / 255.8 ms | 253.9 / 253.0 ms |

计时从 harness 的 speaking→listening 事件到 thinking，每格 2 次平均，不是最后声波到首个可听音。32 次均无异常、各提交 1 条用户消息和 1 条 Agent 消息。低评分短句仍落入 3 s 等待，说明**调度重构不能替代模型与交互策略优化**。

### 3.2 单模型、级联、共同确认

沿用 175 个话轮调参 / 169 个话轮保留测试，后者有 301 个句中停顿。只在调参集选择阈值和时序。下表为 Pi5、调参集 5% 误截断预算；不代表保留集达到 5%。

| 方案 | 保留集误截断点 | 最终停顿平均等待 | 超时触发率 | 平均 EOT 调用数 |
|---|---:|---:|---:|---:|
| FireRed 单模型重新调参 | 16/301，5.3% | 1,000 ms | 100% | 1.00 |
| mini 单模型 | 29/301，9.6% | 808 ms | 23.1% | 1.00 |
| mini 不确定时级联 FireRed | 22/301，7.3% | 887 ms | 12.4% | 1.70 |
| mini 与 FireRed 共同确认 | 17/301，5.6% | 966 ms | 82.8% | 2.00 |
| TurnSense 1.0 单模型 | 18/301，6.0% | 991 ms | 27.2% | 1.00 |
| TurnSense 不确定时级联 FireRed | 17/301，5.6% | 970 ms | 24.3% | 1.18 |
| TurnSense 与 FireRed 共同确认 | 16/301，5.3% | 1,000 ms | 100% | 2.00 |

FireRed 该工作点退化为固定 1 s 超时，不能解释成模型提升。TurnSense 级联只少截断 1 点、提前约 21 ms，95% 按话轮聚类 bootstrap 区间分别约 3.1–8.9% 与 2.9–8.6%，高度重叠；没有依据为这点收益长期承担第二模型的成本。mini 的更快与更多误截断也说明 AUC 第一不等于给定工作点的产品最优。

回放在停顿 200 ms 取固定因果快照；文字为 500 ms 延迟的参考词，不是真实 ASR。级联没有获得更晚的新文字；并行耗时使用两模型耗时最大值，没有模拟 CPU 争用，属于乐观估计。调用数按全部决策点统计，只含 EOT。结果不能当成线上抢话率或直接抄作上线参数。

另外保留了 FireRed 阈值 0.5、250 ms / 3 s 的同快照参考结果，但它没有模拟生产 VAD 500 ms 与真实文字到达，**不使用该值描述当前产品误截断率**。当前产品的直接基线证据是上节实际 AgentSession 测量与真实链路记录。

## 5. 产品体验：完整性、意图与业务边界

“说完了”“愿意交出话轮”“需要回答”“允许工具执行”必须分开。缺少目的地的订票问题也可能已经说完，Agent 应澄清；“先别回答，我还没说完”是完整句子，却明确禁止接话。不要把业务参数完整性写进 EOT 模型。

当前四标签 keep/stop/reply/wait 将 wait 映射到 UNCERTAIN，无法表达持续的明确等待。新契约应区分下列状态；声音控制和新请求提交分别执行：

| 交互状态 | 旧播放 | 新请求 |
|---|---|---|
| keep：附和、无需接话 | 保持或恢复 | 不提交 |
| stop：明确停止 | 终止并完成收尾 | 不自动生成回答 |
| explicit_wait：明确让我等 | 让出声音，持续等待 | 普通 endpointing 超时不允许提交 |
| pending：用户表达尚未完成 | 必要时让出声音 | 等待后续内容，同候选聚合 |
| ready：用户交出话轮、需要回应 | 需要时终止旧输出 | 同版本结束证据及收尾完成后提交 |
| uncertain：缺少证据或歧义 | 保守、有界处理 | 不能伪装成 ready；会话结束与回答授权分离 |

30 个自编边界样例、各重复 2 次的真实 DeepSeek v4 flash 实验：

| 方案 | 结果 | 延迟 |
|---|---|---|
| 当前四标签提示 | 10 次明确等待中 3 次 wait、5 次 stop、2 次 keep；表达不完整样例在 reply/wait 间分布 | p50 1,243 ms；p95 1,824 ms |
| 显式六状态提示 | 56/60 标签匹配；明确等待及 pending 各 10/10 | p50 1,253 ms；p95 1,985 ms |
| 同请求先决策后回答 | 单次 29/30 匹配；非 ready 输出回答 0 次 | 决策首行 p50 1,041 ms、p95 1,435 ms；有回答样例首文本 p50 1,012 ms |

四标签不是同一分类空间，不做伪精确的跨方案“准确率提升”。旧 reply 可以正确表示让旧输出停止，不能据此认定错误生成了新回答。六状态与同请求实验都来自同一批自编样例，不是独立测试集，次数也不足以证明生产稳定性。引用“别说了”的完整问题仍被错误标为 uncertain，是必须保留的反例。

**目标流程：音频 EOT 触发候选推理；在同一次 Agent 推理中先返回交互决策，对 ready 的回答先暂存；Channel 的唯一提交屏障确认候选版本、等待状态和旧播放收尾后，才允许外发回答、持久化正式历史及执行工具。** 对打断路径复用已有意图调用；同一个候选不要分类两次。普通轮次不再另串联一个完整性 LLM。

该方案借鉴已有 deferred finalization 设计，但本项目必须先定义 provisional inference / commit / discard 契约。当前 preemptive 开关不等于这个契约，不能直接开启就称为实现。不可撤销工具必须在 commit 后调用；如果模型先请求工具，应暂存调用意图，不能先执行再补校验。继续说话或文本修订时丢弃旧回答及工具意图。网络超时、解析错误、SDK 关闭流默认 1.0 均为无有效证据，不是用户授权。

## 6. host 与硬件：需要差异化到什么程度

需要差异化，但配置依据是**有效 CPU 分配、并发会话、内存余量、ASR/TTS 是否同机，以及实测运行时表现**。CPU 型号或系统名只是索引。复用 Models 已有 CPU allocation 契约与 Ops 部署配置；不在 Channel 再维护另一套硬件探测系统。

以下是双会话共享 ONNX 权重、会话前端独立的实测。每格 72 次；含特征处理，不含网络/I/O；CPU 是进程 CPU 时间 / 墙钟时间。Mac 无法设置 nice，Pi 使用 nice=10。运行较短、按顺序执行，不能把小差异当作稳定容量保证。

| 模型 / intra-op | Mac p95 / CPU 核当量 | Pi5 p95 / CPU 核当量 |
|---|---:|---:|
| FireRed 默认 0 | 21.7 ms / 6.73 | 169.2 ms / 3.74 |
| FireRed 2 | 35.6 ms / 2.94 | 150.2 ms / 2.89 |
| FireRed 4 | 22.5 ms / 4.87 | 131.4 ms / 3.45 |
| TurnSense 1.0 默认 0 | 44.2 ms / 6.90 | 254.7 ms / 3.69 |
| TurnSense 1.0 2 | 50.2 ms / 2.95 | 221.7 ms / 2.83 |
| TurnSense 1.0 4 | 34.5 ms / 4.93 | 277.1 ms / 3.75 |

Pi5 TurnSense 从 2→4 线程更慢；FireRed 却更快，说明不能统一假设“线程越多越好”或“2 线程一定最快”。独立双模型实例实验中 FireRed 默认线程 Pi5 p95 为 253.7 ms，不能用它替代生产共享权重结果。共享权重减少内存，但不自动消除 CPU 争用。

原生 mini 单/双实例的 p95：Mac 6.5/9.8 ms，Pi5 120/259 ms；该后端未提供与本次 ONNX 相同的线程旋钮，没有伪造一个 `threads=2` 配置。mini 的 host 策略应先限制预测并发和候选触发频率。

建议的初始配置（待产品负载验收，不是已证明的容量上限）：

| 配置项 | Mac M3 Pro / 36 GiB | Pi5 / 8 GiB |
|---|---|---|
| 首个音频集成主模型 | mini | mini；TurnSense 1.0 同接口备选 |
| 纯推理同时执行数 | 从 1 开始，负载验收后允许 2 | 从 1 开始；有界等待，过期候选丢弃 |
| ONNX 候选预算 | 2 线程作为共存起点；有独占预算再测 4 | 2 线程作为共存起点；不得默认占满四核 |
| 队列 | 复用候选生命周期，每会话只保留最新待评分版本，公平调度 | 同样规则，严格限制总待执行数量 |
| 同机 ASR/TTS | 纳入整机预算 | 尤其需要预留音频、ASR/TTS 与服务线程预算 |
| 语义动作 / 明确等待 | 与 Pi5 相同 | 与 Mac 相同 |
| 模型阈值 | 随锁定配置校准 | 不照抄其他运行时阈值；当前 mini 一致性不能外推所有版本 |
| GPU/NPU | 未验证，不默认启用 | 未验证，不假定加速卡可用 |

配置应包含 model hash、frontend/runtime 版本、阈值与时序、线程预算、最大在途任务数和降级策略；会话启动时冻结。过载或推理失败记录 unavailable/timeout，走显式保守状态；不以错误高分提交，也不在一句话中途切换模型。

## 7. 项目职责与实现顺序

| 项目 / 组件 | 应拥有的职责 |
|---|---|
| Channel | 候选、文本修订、交互状态、证据一致性、唯一提交、播放收尾 |
| LiveKit SDK | 音频/检测流生命周期、endpointing 与播放基础能力；通过既有扩展点接入 |
| Models | 权重与前端工件、运行时装配、CPU 预算契约；不拥有产品话轮状态 |
| Agent | 对候选的暂存推理、业务澄清、commit 后工具与正式历史；不接管毫秒级音频调度 |
| Ops | host 配置、版本锁定、健康检查、灰度与回滚 |
| BOX3 / 客户端 | 音频采集、AEC、播放事实与会话信号；不自行判断业务请求完成 |

实施顺序：

1. 在现有协调器内补齐 explicit_wait / pending / uncertain 的区别，冻结证据身份；先保留 FireRed。纯推理移出所有事件循环热路径，使用有界执行器；共享只读权重，会话可变状态仍由 owner loop 持有。
2. 将纯 EOT 评分与 settle 并行，保留提交前的旧 SpeechHandle 收尾屏障；结果需匹配 candidate、generation、revision 和音频截至时刻。补齐取消、乱序、继续说话、重复 final 的故障验证。
3. 接入 mini 原生流，作为同接口的单模型候选；统一校准 VAD/ASR/EOT 的时间轴。先做影子记录，再做冻结参数的完整组合 A/B。不得把 mini 的 SDK 默认 endpointing 与 FireRed 的 Agent override 混用。
4. 建立 Agent 暂存推理契约，将交互决策与生成合并到同一次请求。单独测试工具、历史、播放三个副作用屏障。该步骤完成前保留预生成关闭，不给每个普通轮次临时补一个串行分类器。
5. 在真实设备负载下选定 host profile，先灰度后切换；不长期保留双主模型投票。TurnSense 只有在相同产品门槛下优于 mini 才替换。

## 8. 产品验收与本轮未闭合项

Mac 真实组件测试：预检曾返回转写（约 23.5 s），3 条正式组件 ASR 均超时；VAD/TTS/EOT 各 3 条执行完成，其中 TTS 完整合成约 1.1–1.9 s。EOT 组件的 pass 只代表执行成功，不代表正确判断。随后实时推送音频的 3 条流式探针及 3 条复核均未在观察窗口返回非空 final，不能用预检成功覆盖正式失败；当前没有确认根因。

另加 1 条延长观察的时序探针：推送音频与尾部静音后再等 25 s，仍只有 `stt_stream_started`，没有完成连接/任务握手后的 `stt_ws_connected` 或首音频事件。因此本次该失败位于 ASR 建连/任务启动阶段，尚不能细分为网络、WebSocket 或服务端任务握手原因，不能归因于 EOT 判定。原始记录为 `results/mac/streaming-asr-trace.json`。

Pi5 相同实时流式探针 3/3 返回非空 final，最后有效音频到最后 final 约 473、1,040、471 ms；静音边界使用 PCM RMS 判定，非物理声学测量。停顿素材产生两个 final，犹豫素材产生“あ。那个。帮我查一下明天的天气。”，再次证明 ASR 分句不能直接作为产品请求结束。

这部分说明，**host profile 还要包含真实 provider/network 路径的验收，不能只跑本地 ONNX**。本轮没有证据将 Mac 失败归因于 EOT，也没有修改无关生产代码来掩盖失败。

后续产品 A/B 应使用同一批真实多人中文/混说录音、麦克风与播放条件，冻结基线、新方案和模型参数，并按人/会话划分校准与保留集。比较单位是完整交互；同一录音分别测同架构换模型、同模型换调度、完整组合，避免同时变化无法归因。

| 验收维度 | 记录与选择规则 |
|---|---|
| 抢话与丢尾句 | 按完整请求统计，分句中停顿、修订、长犹豫；配对置信区间，不能只看平均分 |
| 明确等待 / 附和 / 停止 | 独立类别；任何明确等待后自动回答、错误工具调用均阻止发布 |
| 接话速度 | 最后有效用户音频→commit→首文本→首个设备可听音，报告 p50/p95/p99 |
| 打断体验 | 用户起声→降音、取消→设备静音、假打断恢复、旧声音残留 |
| 副作用与生命周期 | 继续说话后旧推理不得执行工具、写正式历史或播放；不得重复提交 |
| 系统能力 | 双会话/ASR-TTS 同机/高负载、队列时长、循环延迟、内存、温度与降频 |
| 故障 | 断网、ASR 延迟、EOT 超时、解析失败、模型不可用、断连重连 |
| 产品选择 | 先满足状态正确性，再在相同误截断预算下选可听延迟较低者；没有明显收益就保留更简单方案 |

以上是发布门槛与下一阶段验证要求，不是已通过项目。本轮足以决定重构方向、否决默认双 EOT 级联、选择首个集成候选和 host 调参方式；不足以替代完整新实现的物理设备验收。
