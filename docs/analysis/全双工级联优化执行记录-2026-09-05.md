# 全双工级联优化：第一批实施与验证

> 本文保存第一批结果。后续修正和最新测试见[第二批执行记录](全双工级联优化第二批执行记录-2026-09-05.md)：final/停声顺序与重复裁决已修复，意图区分缺口仍保留。

本轮在独立工作区实施，基线为 `7204c7932025e309404ca9b48ad006e4a3979132`。没有修改原工作目录、发布服务或新增产品热词表。目标仍未全部达成：语义双讲有明确、可复现的验收缺口，不能把本轮通过项解释为“全双工体验已达标”。

## 已实施的架构修正

| 问题 | 修改 | 验证依据 |
| --- | --- | --- |
| 音频绕过 LiveKit 1.7 自动插入的 sink proxy，播放完成不收敛 | 帧和播放事件经过同一条公开 AudioOutput 链 | 生产 Agent 冒烟从超时恢复；三种模式真实级联 |
| 欢迎语、主动播报、错误提示强制 `allow_interruptions=True` | 固定播报继承会话 owner；channel/half 明确关闭 SDK 的自动恢复策略；PTT 显式 manual、按键仍走 forced interrupt | 两种流式模式欢迎语 SpeechHandle；PTT 实际抢占 |
| 暂停缓冲满后静默丢音；恢复依赖下一帧；重复 duck 清空尾音 | 在既有 OutputController 中统一串行写入，缓冲容量施加背压，恢复主动排空，重复暂停幂等 | 修改前 7 个竞态用例全部失败，修改后通过 |
| cancel/clear/reset 期间等待中的旧音频仍能写入 | 写入绑定 generation，失效时取消正在等待的 sink 写入；排空逐帧重查状态 | cancel、clear、reset、排空中再次暂停四类交错 |
| 暂停中的 TTS 已结束却提前 flush | 排空后才向 sink flush；尾音写入失败则通过 clear 终止播放等待 | 尾音完整性、失败终止测试 |
| ChineseModel 的 ASR/VAD/冷却状态跨会话共享 | 每会话独立 adapter；复用既有 EotManager 的 ONNX 权重注册表 | 两个会话互不污染，backend 仍是同一实例 |
| 连续高频 interim 让防抖长期不触发推理 | 以最后一次推理的单调时钟为节流基准 | 连续 90ms interim 的推理进展测试 |
| 短 final 被长度门槛丢弃，短 interim 清分不一致 | 所有非空 final 正常评分，短 interim 同时清理两份分数状态 | 好、7、停、嗯、no、对；没有按这些词写产品分支 |
| E2E 实际绕过产品回调；真实服务凭据被测试占位符覆盖 | 复用生产 Agent/bind_session、既有 headless 音频输入输出；显式 env 优先；生产链测试严格清理 | 模拟链、真实服务链分别验证 |

没有另造会话引擎、音频播放器或模型注册表。SDK 继续负责生成、端点和播放调度；现有协调器继续负责产品话轮。OutputController 只管音频准入、顺序和失效。

背压缓冲允许一个超过配置容量的 provider 帧，避免零容量/大帧死锁；内存上界是配置容量与一个 provider 帧中的较大者，加正在写入的帧。这里限制的是 channel 缓冲，不能代表远端 TTS 服务也停止生成。`played_seconds` 仍是送入 sink 的样本量，并非设备实际播放 ACK。

## 场景与证据分层

### 生产回调链模拟 E2E

复用 `tests/_harness`，经过生产 Agent、生产事件回调、真实 LiveKit 1.7.1、真实 EOT 模型和实际 PCM sink。STT、VAD、LLM、TTS 事件按脚本产生，音频是确定性波形；这一层验证时序和逻辑，不验证真人识别率或口音。

16 类说话方式：快说、慢说、口吃式重复、重复 interim、自我纠正、犹豫、短回答、单个数字、长号码、英文、中英混合、引用命令、否定命令、长条件句、句中停顿、延迟 final。全双工/半双工分别运行，PTT 复用相同输入画像，但以按键释放为唯一提交边界。

补充：欢迎语 owner、播报中短噪声、PTT 重复按住/释放、播报中按下抢占、短按只停止；以及真正发生在播报期间的 5 个语义双讲验收用例。

**结果：54 通过、4 strict xfail。** 后者就是尚未解决的产品缺口，不计入通过率。`--runxfail -k overlap_intent` 会直接显示失败，意外通过会触发严格失败，要求重新审查契约。

逐案例证据：[human-matrix.json](voice-validation/human-matrix.json)。

### 真实服务级联

复用仓库已有基准语音 `benchmark/audio/generated/normal_ask_intro.wav` 和 ffmpeg 的保留音高变速，不重新生成测试素材。输入为“帮我详细介绍一下这个方案。”。

| 语速 | 输入时长 | full_duplex | half_duplex | PTT |
| --- | ---: | --- | --- | --- |
| 0.7× | 4.206s | 通过 | 通过 | 通过 |
| 1.0× | 2.948s | 通过 | 通过 | 通过 |
| 1.4× | 2.103s | 通过 | 通过 | 通过 |

**9/9 通过。** 都调用了真实 Bailian ASR、已配置的 direct LLM、Bailian TTS；流式模式另经过真实 FireRed pVAD/EOT，PTT 按设计不用 VAD/EOT 提交。9 次识别均正确，均产生有效回复音频。另有独立 STT/TTS smoke 通过。

本层是 **direct_llm 分支 + 内存音频 sink**，不是带房间鉴权的 eidolon_agent RPC 部署，也不是 RTC 网络或扬声器实测。PTT 的 PCM 按段注入，流式模式按实时速度回放。回答的生成耗时不等于设备播完耗时。这 9 例不能推断口音、远场、AEC、真实双讲识别率或延迟 P95。

证据：[real-cascade.json](voice-validation/real-cascade.json)、[provider-smoke.json](voice-validation/provider-smoke.json)。独立 smoke 初次运行时 VAD 资源是 LFS 指针，STT/TTS 检查不依赖 VAD；后续真实级联显式加载已展开的 pVAD，且 VAD 加载失败即失败，未静默降级。

### 回归与环境

锁定基线 SDK 为 livekit-agents/plugins-openai 1.7.1，RTC 1.1.15，API 1.2.1，protocol 1.1.26。工作区 `.venv` 从已有缓存装入这些版本，其余依赖复用原环境只读路径；未修改原 `.venv`，未整体升级至 1.8。CI 应按 `uv.lock` 建立完整干净环境，本地复用依赖不等于干净安装验收。

ONNX 使用原目录已展开文件，通过 `EIDOLON_EOT_MODEL_DIR` / `EIDOLON_FIRERED_PVAD_MODEL_DIR` 显式指定；未把 LFS 指针误当可运行模型。普通套件中的 ONNX fixture 也尊重前者。

**最终回归：1012 通过、2 跳过、13 原有 strict xfail。** 覆盖 agent、EOT 与复用的 headless 测试框架。

回归统计及原有预期失败：[regression-summary.json](voice-validation/regression-summary.json)。音频控制器相关 46 项通过，包括新增的 sink 断连后终止等待。原有 13 项 EOT 产品契约预期失败仍然存在，本轮没有移除或放宽它们。修改涉及的 Python 文件经 Ruff 检查，diff 经空白检查。

## 未达标的双讲验收与方案反馈

| 编号 | 播报中的用户发言 | 应有行为 | 实测缺口 |
| --- | --- | --- | --- |
| FD-INTENT-1 | 好的 | 保留原回答 | 当前误取消 |
| FD-SETTLEMENT | 嗯嗯你继续 | 及时恢复原回答 | 2 秒观察点仍暂停 |
| FD-INTENT-2 | 不要停止，请继续刚才的解释 | 保留原回答 | 当前误取消 |
| FD-INTENT-3 | 不是，我说的是明天 | 及时接管话轮 | 2 秒观察点未打断 |

同批“停”成功打断；它没有被加入热词表。真实 EOT 分数分别为：好的 0.7427、嗯嗯你继续 0.0020、不要停止… 0.9348、更正句 0.1182、停 0.9859。这说明**完句分数和打断意图必须分离**，不是再调一个阈值就能解决。

下一阶段依赖与实施顺序：

1. **独立意图证据，再统一裁决。** 当前 intent classifier 是 Noop，ONNX 分类器是未实现占位。优先验证现有 LiveKit native adaptive 服务能力，与 channel owner 做同一套重叠语音对照；若使用独立分类器，应接已有接口并测中文否定、引用、更正与附和，不能用案例词表冒充模型。必须验证 resolved owner 和服务失败后的回退，不能仅看到配置值就认定接入成功。
2. **移除双重裁决的副作用。** `should_interrupt()` 的推测不应提前记录真实打断；候选 generation、response 身份、意图证据、EOT/VAD、provider final 应形成一次可追踪的裁决，真实取消成功后才记录冷却。未拿到意图证据之前，不凭空把现有分数当语义模型。
3. **统一话轮收敛与暂停截止。** final、VAD stop、延迟 final 和 merge continuation 进入同一候选结算；解决已有 final 仍等待长 HOLD、旧完成钩子阻塞新话轮的问题。不能简单把六秒改成几百毫秒而丢掉慢说/纠正。
4. **补全真实重叠与设备链。** 扩展现有真实语音素材中的附和、更正、停顿和回声，叠加播放录音与噪声，经真实 ASR 后运行上述冻结验收；再接 RTC/实际播放 ACK、response 关联以及 Agent RPC 中断上下文传递。当前内存 sink 不具备这些证据。

这些门槛通过前，本轮改动适合作为可审查的基础改造，不能直接等同于上线验收。
