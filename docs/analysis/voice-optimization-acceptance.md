## Channel 输出内容保全与送帧核查（2026-09-08）

## 按机制审查等待与恢复，拒绝按 FINAL 快捷恢复（2026-09-08）

用户要求泛化处理后，本轮先审查等待的证据含义。ASR 句段定稿、VAD 停声、用户话轮结束和打断意图是不同事实；不能因为已有 FINAL 就推断没有后续输入，也不能把 EOT 中间分数解释为附和。

| 机制／场景 | 当前证据与应保持的边界 |
| --- | --- |
| 用户仍在说，或分句后短暂停顿 | FINAL 可能只覆盖一个句段；不得把它单独作为恢复或提交依据 |
| 停声后转写尚未到齐 | 等待的是外部转写证据；不能将无文本误称为已确认噪声 |
| 转写已定稿，配置的意图请求仍在执行 | 等待的是现有分类请求，结果必须绑定当前候选、声学代次和转写版本；不能再造一个分类器或计时器 |
| 默认策略收到 FINAL，但完成度／意图仍不明确 | 当前没有待返回的意图请求；6 秒窗口仍允许后续证据，不能把这段时间描述成模型推理耗时，也不能凭定稿直接判附和 |
| 已取得可执行的停止、接管或恢复证据 | 沿现有唯一裁决入口执行，不能继续等满兜底时间 |
| 证据预算耗尽 | 这是不确定状态下的兜底恢复，不等于正确识别了附和；恢复内容完整性与恢复时机分开验收 |
| Channel 已执行 duck／resume，但接收端未变化 | 检查下游排队与真实音频，不用裁决时间冒充实际播放时间 |

对“默认策略已有 FINAL、VAD 已停就立即恢复”的假设做了进程内对照，只替换 Channel 纯 decider 的返回，未修改 SDK 或工作区运行实现。复用真实 AgentSession、生产 Pipeline、原转写拼接和输出控制，新增日期、人数、英文目的地三种连续修改表达，各覆盖 FINAL 在 VAD 停声前／后到达；中间停顿 400 ms，仍在现有 800 ms 合并窗口内。EOT 边界注入前段 0.4、后段 0.95，明确隔离模型准确率，不将其计作真实模型或 RTC 验收。

当前实现六项均通过：停顿中保持让声，后续完整文本只形成一次新回复。快捷恢复草案六项均在停顿中恢复原播放，违反连续表达的让声断言；最终文本仍完整提交，没有观察到丢字或重复提交，不能夸大失败类型。因此拒绝这项草案，也不将其转换为短词、语言或特定分数的例外规则。原始对照与最终回归见 [机制验证](voice-validation/interruption-mechanism-validation.json)。

证据见 `voice-validation/mobile-opi5max-pause-feedback.json`。两段文本均进入 ASR。第一段低 EOT（约 0.0005；重试约 0.0034）在 sentence FINAL / VAD idle 时触发 `final_terminal_eot_low` rollback。后续开口分别在 rollback 后约 0.41 / 0.45 秒，日志明确显示 800ms cooldown 跳过 duck；后续文本走 `attention_blocked`，没有正式提交。第一次前缀候选被后续开口替换；另一次成功合并成“人数方面。改成两个人。”，仍未提交直到 session close。因此既有恢复裁决过早的问题，也有恢复后续句重新准入的问题；不能归因为 ASR 漏字或简单扩大拼接窗口。

这暴露了此前脚本测试的边界：停顿续句测试注入 0.4 / 0.95 的 EOT 分数，没有覆盖实际低 EOT 触发恢复的分支。59 项通过不证明这条真机路径正常。下一步应复现低 EOT + 句级 FINAL + 停顿续说在冷却窗口内外的通用机制，并覆盖真实附和、噪音和重复开口；修正应沿现有 Channel 裁决与候选生命周期，不增加热词规则、第二套编排或第三方 SDK 修改。

用户反馈为定性听感，没有设备扬声器时间戳，不报告物理停止延迟或 P95。成功室内活动轮服务端 VAD onset 到 cancel 约 493ms；此值不等于耳朵听到的停声延迟。公园问题日志另有一次早先 LLM error，不能将所有尝试均计为通过。

### 暂停续说修复与自动化回归（2026-09-08）

证据归档：[暂停续说恢复验证](voice-validation/pause-continuation-recovery.json)。本轮修复的是“播放暂时恢复后，尚未裁决的用户话轮不能继续收集和处理证据”的生命周期问题。低 EOT 与句级 FINAL 不再直接作终局拒绝；新增非终局 RESUME 动作，在既有继续说话保护窗口后允许恢复输出，同时保留同一候选的证据等待。冷却只限制重复播放操作，不再拦截已准入候选的后续转写。候选身份和代次一致、仍在原有证据期限内时，后续声学句段复用既有文本组装；已经裁决的候选不会重新打开。

实现复用原有 800 ms 合并保护窗口、6 秒证据预算、候选/代次、文本组装和定时任务入口，没有增加热词、第二套队列或新的 SDK 编排。窗口数值未改，但用途发生明确变化：默认无意图模型路径的播放等待与证据等待分离；语义候选可能跨越声学合并窗口继续存在。已配置意图模型的路径保留等待模型结果的策略。暂时恢复不取消语义稳定性复查；弱证据等待通过既有复查任务到期重评，避免没有后续 ASR 事件就永远等不到裁决。

自动化验证不是只增加原话示例：框架层覆盖中文日期、人数和英文目的地，FINAL 在 VAD 停声前/后到达，前段/后段 EOT 为 0.003/0.424、0.003/0.95、0.4/0.95 的 18 种组合；另覆盖播放恢复后的迟到 FINAL、冷却窗口内外重新开口、长时间仍在说话、无续说时到期回收，以及原模型结果迟到、错误、显式抢占和恢复内容完整性。最终相关单元/基准测试 400 项、框架场景 46 项全部通过。框架场景注入模型边界分数，不冒充真实 ASR/EOT 准确率。

真实 RTC 首轮三条均失败，暴露了仅依靠声学合并窗口和 completed-turn 回调的草案不足；最终移除该回调兜底草案，修复候选生命周期。第二轮功能已形成完整请求，但原报告把同一 RPC 的重复 timeline 快照算成多个请求；现按房间、话轮及请求发送时间去重，另测同话轮两次真实发送仍计为两次。费用用例按 ASR 数字格式验收。失败原始报告保留，没有重写为通过。

冻结运行源码后，原 managed-worker 基准在 Mac 独立 worker/房间使用真实 STT、EOT、Agent RPC、TTS 和 RTC 接收端，最终三条功能用例全部通过。人数片段间分别插入 500/900 ms 静音，费用片段插入 500 ms；这不是测得的 VAD 停顿时长。每条均提交完整前后文、取消旧回复，恰好两次 RPC（初始问题一次、完整修改一次）。未将此结果解释为实体 mobile 外放验收。
