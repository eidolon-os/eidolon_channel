# 交互意图分类：pplx / d3 与 DeepSeek Flash 对照

日期：2026-10-17。状态：真实服务隔离比较完成，生产未改动。

后续已完成保持生产四标签契约的替换验证、真实 SDK 接入及故障测试；以[意图识别模型替换评审](intent-replacement-validation-2026-10-17.md)为准。特别是固定 0.8 门槛已复现漏答，本页早期高置信样例结果不能作为上线阈值依据。

## 决策

两个服务均适合替换 `LlmInterruptClassifier` 背后的生成式分类调用；替换对象是交互意图判断，不是 mini 的音频 EOT，也不是负责业务回答的 Agent LLM。

优先将 **d3 作为低延迟影子集成候选，pplx 作为质量对照**。本次 pplx 原始标签匹配更多，d3 网络往返更快；尚不足以确认生产胜者。不能把文档的通用模型路由准确率迁移为对话控制准确率。

这项新证据修订此前方案：独立快速分类器的成本显著低于生成式分类，因此优先验证“mini + 单个 decider + Channel 提交门控 + 原有回答 LLM”。暂存推理/同请求决策与回答可以保留为后续优化，不再是降低分类延迟的前置条件。

## 实测口径

- 服务接口来自用户提供的 `/Users/manson/ai/decider/delta_router_eval/docs/decider-api-usage.md`；两端实际调用 `/pplx/v1/systemone` 与 `/d3/v1/systemone`。
- 使用上一轮相同的 30 个自编中文边界样例；每模型、每 host 重复 2 次，共 240 请求。不是 240 个独立样例。
- 一次 choice 问题、六个具体选项：keep / stop / explicit_wait / pending / ready / uncertain。输入包含 assistant_text 和 user_text，不含真实用户会话。
- 请求前冻结说明与选项，未根据错误调提示后重算成绩。两模型交替次序、串行请求、连接复用；客户端禁用环境代理，5 s 请求超时，未做压力测试。
- 延迟从发起 HTTP 请求到解析并校验响应，包含 host 到服务的网络往返和服务排队；不是 GPU 内部耗时。
- DeepSeek 六状态结果复用此前真实调用，未在本轮同时重跑。因此延迟是参考对照，不能解释成相同服务器负载下的严格性能比值。

## 结果

| 模型 | 每端标签匹配 | Mac p50 / p95 | Pi5 p50 / p95 | 接口失败 |
|---|---:|---:|---:|---:|
| pplx | 58/60 | 254 / 953 ms | 222 / 776 ms | 0/120 |
| d3 | 54/60 | 132 / 244 ms | 136 / 163 ms | 0/120 |
| DeepSeek Flash 六状态分类，前轮参考 | 56/60，仅 Mac 请求 | 1,253 / 1,985 ms | 未测 | 0/60 |

两端返回的类别与错误样例相同。本次两模型明确等待、明确停止、pending、ready 样例的原始标签全部匹配。pplx 的错误来自一个不同样例，d3 来自三个；重复调用不能提高独立样本量。

| 错误样例 | 期望 | pplx | d3 |
|---|---|---|---|
| 当前讨论架构：“先别换话题，就讲刚才那个。” | keep | keep | ready，最大概率 0.377 |
| 当前讨论几个方案：“那个。” | uncertain | uncertain | pending，0.411 |
| 缺少前文：“就按刚才那个。” | uncertain | ready，0.512 | ready，0.421 |

引用“别说了”的完整问题，两者本次均判为 ready；此前 DeepSeek 六状态提示对此样例判为 uncertain。这里只说明具体对照，不能外推对引用或否定处理的整体优劣。

按服务文档已有的最大概率 ≥ 0.8 分组，两者每端均接受 46/60，其中 46/46 标签匹配；其余 14/60 应视为拒判，不能算作正确预测。接受覆盖率为 76.7%，且两个模型接受的样例集合不完全相同。明确等待样例各有 2/10 未达到阈值，不能只关注错误被过滤而忽视正确状态未被接受。

**0.8 不是本项目已校准的安全阈值。** 六分类概率需要在独立产品样例上校准，并同时报告错误接受、拒判、等待状态漏检和最终体验。模型 confidence 字段没有用于此次分组。

## 接入方式与耗时

建议流程：

```text
音频 → VAD / mini ────────→ 结束证据
ASR 文本 + 必要对话上下文 → d3 或 pplx → 交互意图证据
                            ↓
              Channel 校验候选版本、状态和播放收尾
                            ↓
                    原有 Agent 回答 LLM
```

决策服务只返回类别与概率，不生成回答，不能替代原有回答模型。两个 decider 每次只选一个，不默认同时投票，也不默认把低置信请求再串行送另一个模型。

文本到达足够稳定的版本后启动分类，允许与 mini、静音等待和旧播放收尾并行。若分类比其他条件先完成，则不增加关键路径；若分类最后完成，新增的是剩余等待时间。不能把“d3 136 ms”直接写成整体增加 136 ms，也不能承诺完全隐藏。

低置信或超时记录为未获得有效意图证据；保持已有明确等待状态。随后结合新转写、继续说话和既有有界策略处理，不自动授权回答；也不无限挂起会话。高置信概率同样不是工具授权。

## 工程边界

- 当前 `LlmInterruptClassifier.classify(text, assistant_text=...)` 的异步调用位置可复用，但不是换 OpenAI base_url 就能工作：需要一个 SystemOne HTTP provider 适配器。
- 四标签兼容模式可映射到现有意图类型；要表达六状态，仍需扩展 Channel 的状态/结果契约。不能将 explicit_wait 简单映射 UNCERTAIN 后声称实现了明确等待。
- 分类器只返回证据及模型版本、概率和状态；candidate/generation/revision 校验、deadline、取消及播放副作用仍由 Channel 持有。
- 输入应是有限的结构化对话上下文与当前用户文本。生产需要补当前等待状态及必要历史；本次仅验证与旧实验相同的 assistant_text/user_text，未验证长历史或多轮恢复。
- 先校验响应字段、选项集合、概率范围及总和。连接、超时和并发独立配置，异步 HTTP 不阻塞事件循环；旧候选的迟到结果丢弃。
- 两台 host 调用同一个远端服务，没有本地 27B 权重或 GPU 需求。差异主要来自网络路径，不能据此给 Mac/Pi5 强制分配不同 decider。
